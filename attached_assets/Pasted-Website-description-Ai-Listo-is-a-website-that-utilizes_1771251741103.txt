Website description:
- Ai-Listo is a website that utilizes a trained YOLO model for assessing student attention state in real time. The website will let user to select a camera from all the detected camera devices, and the website will show the live preview from the camera and the real-time annotation of students from the YOLO model below it.

Key Requirements:
- Login or Sign-in: email and password fields with show password toggle button, forgot password and "Don't have an account? Register here" links or buttons.
- Register or Sign-up: first name, last name, email, password and confirm password fields with show password toggle button.
- Forgot or Reset Password: email field and a button for sending reset password email. Another page for the landing page of the reset password email with new password and confirm password fields with toggle buttons to see password.
- Branding: Incorporate 'Ai-Listo', 'SSS Vilage Elementary School', and 'SSSVES' branding elements, think of colors that are appropriate for a school website and are pleasing to the eyes. Keep in mind that the system/website is called Ai-Listo, the school is just a client.
- Tech Stack: use HTML and CSS for frontend development.

Core Features:
- Navigation: a sidebar containing links for dashboard, live session, classes, history, reports, and about; and profile and log out button at the bottom.
- Dashboard: statistics of sessions (attention overview, attention distribution over time, class engagement metrics, model performance metrics).
- Live Session: a dropdown to select the class/subject and section, a button to select the camera device to use. After selecting camera, show the live preview of camera and the live annotation of YOLO model below it. Add start, pause, end and save buttons to control the session. At the very bottom, show live session statistics about student attention state (output from the YOLO model).
- Classes: shows the subjects and sections handled by the user (teacher) with schedules. Include an add subject button that allows the user to input subject name, course code, and section. Schedules should have CRUD features.
- History: shows the list of past sessions containing description (subject and section) and statistics (session summary).
- Reports: contains two dropdown buttons to select subject and section. Allows the user to generate a downloadable pdf monthly for the selected subject. 
- About: description of the system, developer info, version information.
- Profile: contains user information (name, email, role (teacher or admin)), and a reset password link or botton.

Admin Account:
- Additional page for user management. Include it on the sidebar navigation.
- User Management: gives CRUD features to admin. Allows admin to create, read, and edit/update user info, as well as delete users.

Constraint to keep in mind:
- The backend will be Flask, and the database is PostreSQL. REMEMBER, only develop the frontend, and make sure that the frontend must be ready to be integrated with this backend structure.
